# 测试、实验与验收规范

本文是 `01_技术方案.md` 的可执行验收附录。所有数值为拟定门槛或实验起点，不是已经跑出的结果。

## 1. 测试分层

U：无真实模型的单元/性质测试。
C：接口合同与状态机测试，可使用明确命名的 mock。
R：指定完整 revision 的真实权重测试。
N：A800/A100 设备测试。
A：Ascend 910B 设备测试。
E：完整端到端与长流测试。

R/N/A/E 不得因为环境缺失自动跳过后仍计为 PASS；报告 SKIPPED/BLOCKED 和原因。mock 输出必须带 model_kind=mock，不能伪造真实模型路径。

## 2. 强制不变量

I01 模型使用音频终点不超过交付终点。
I02 当前任务的 history/prompt/model/policy 版本可追溯。
I03 已提交文本只通过明确 Correction 更改。
I04 当前音频未翻译/未明确处理的部分不被静默删除。
I05 旧 epoch/generation 的结果不能覆盖新输出。
I06 每个客户端事件具有单调 event_seq；去重不重复提交。
I07 End 的 final 快照覆盖最后确认接收样本，或返回明确未完成。
I08 Cancel 不强制把残缺假设转成成功最终译文。
I09 空音频/静音不得产生未标识的稳定语义内容。
I10 不把模型预测时间戳当作延迟或对齐真值。
I11 计算成本按新增唯一音频计量，不按重叠窗口重复累计。
I12 CUDA/NPU 共用语义合同；平台分支不能改变翻译方向或偷偷换模型。

## 5. 策略、窗口与事件测试

| ID | 条件 | 预期 |
|---|---|---|

| POL02 | 新增音频后 LCP 增长 | 只提交合法稳定候选，尾部保留。 |
| POL03 | 自由假设与已提交前缀矛盾 | 暂停/更正，禁止按旧长度截掉新假设开头。 |

| WIN02 | 模型预测 cue 时间漂移 | 切窗仍受已观察源证据约束。 |

| WIN04 | 长时无停顿到 hard limit | 显式降级/失败，不静默截断。 |
| WIN05 | 新 epoch 与旧假设 | 不直接整段 LCP；源身份和历史正确重置。 |

| EVT02 | 重复 event_seq | 客户端幂等，不再次追加提交。 |
| EVT03 | 旧任务完成晚 | 不能覆盖新状态；丢弃原因记录。 |
| EVT04 | 正常 End | 最后音频覆盖，未解析内容明确返回。 |
| EVT05 | Cancel | 停止/忽略过期结果，不伪造 final。 |
| EVT06 | 断连、服务端仍在运行 | 有界恢复或明确不可恢复，提交不重复。 |
| EVT07 | worker 崩溃/重启 | 不假装旧缓存仍存在；中断可见。 |
| EVT08 | 不同会话相同术语/音频 | 状态绝不串线。 |

## 6. 设备与数值回归

NVIDIA：验证实际 compute capability/wheel/kernel 支持；BF16 基线，FP16/量化分支分别比较。检查冷启动、热态、OOM、形状变化、实际 attention 和线性算子路径。

Ascend：检查 CPU 架构/驱动/固件/CANN/TorchNPU 组合、所有组件在目标设备的真实执行、CPU fallback、mask/index/位置/状态 dtype、同步和动态形状。

数值测试顺序：同一 CPU 波形 → mel 有效区 → audio tower → connector → embedding 注入 → decoder 指定单步 → teacher-forced 固定目标 token → 自由生成。

每一层记录 shape、dtype、device、NaN/Inf、绝对/相对误差分位数、可选余弦相似度；logits 记录 top-k、排名和 margin。首先测同平台重复运行及精度转换的基线差异，再冻结跨平台阈值。

自由生成不同不能单凭字符串不一致判断硬件错误；自由生成相同也不能证明内部状态正确。使用 teacher-forced 路径定位首次差异，结合终端质量验收。

若加入缓存优化，增加同一快照无缓存/缓存对照，覆盖音频新增、长度桶切换、epoch 切换、取消、重置、不同会话和不同语言；递归/卷积状态与 KV 一并检查。

## 7. 实验设计

### 7.1 配置轴

模型：2B / 9B。

策略：B0 offline / B1 boundary / B2 LA2 / B2 LA3 / 后续 B3。

输入：完整句、增长前缀、长流、真实麦克风。

平台：A800、A100、Ascend 910B，按实际可用设备分别报告。

精度：参考 BF16；必要的 FP16/量化另列。

参数：首次累积、更新间隔、尾部保留、源尾保护、上下文、软/硬窗口、最大生成预算。

先粗筛模型与策略，再做单变量消融，再做少数组合；不要全笛卡尔积浪费设备时间。保留集仅用于冻结方案后的评价，不能边调边报告“最终测试”。

### 7.2 数据拆分

以原始录音/说话人/场景为单位拆分。一个长录音切出的片段和同一片段的多个前缀必须处于同一数据分区。记录授权和样例版本；不同平台比较使用相同样例。

建议：100 条英中短片段用于初期开发/保留各 50；另有专项最小对；1×30 分钟开发长流和不同来源的 3×30 分钟验收流。规模按业务扩展，但任何结果必须写出样本量。

参考译文允许多种合理同传表达；关键命题、数字和极性用人工标签补足自动评分。

## 8. 延迟与计算的精确定义

### 8.1 时间坐标

源音频位置使用 sample_index / sample_rate。真实运行使用单调 wall clock。单机回放可共享起点 T0；跨机器要校准或只在同一观测端计算可比较时差。

每个目标语义单元 i 标注其所需源信息最早已到达的音频位置 e_i。客户端实际展示提交的时刻为 t_i。在同一时钟基准下：

`semantic_commit_latency_i = t_i - (T0 + e_i)`。

e_i 由参考标注/明确评测实现提供，不由模型自己猜的时间戳提供。多个目标单元对应同一源范围是允许的；不要把目标字符均匀摊到音频上制造低延迟。

### 8.2 必报延迟

首条草稿延迟；首条非空且有语义稳定提交延迟；稳定语义延迟 p50/p95；句中正确提交比例；最后音频到达后尾段排空时间；排队/模型/传输/展示分解。

用于触发两次一致的固定更新步长本身会形成等待；不能把该等待从数字中扣除。warmup 与冷启动分开，不把冷启动隐藏成“模型预先存在”。

### 8.3 RTF 与积压

`stream_compute_RTF = 累计实际推理成本 / 源音频唯一时长`。

如果重复窗口包含之前音频，分母不重复累计。可另报单窗处理比，但名称必须不同。

报告 outstanding_audio_age = received_end_time - newest_applied_used_end_time，以及最长待处理年龄、pending 任务覆盖范围和当前缓冲长度。长流回归对后半段积压斜率做检查，不能只看开头平均值。

### 8.4 修订

草稿擦除量按选定 Unicode/评测 token 单位定义并版本化；稳定追加与 Correction 单独统计。最终 transcript 的高质量不能抵消在线期间已经向用户提交过错误内容的事实。

## 9. 长流与容量

先独占单卡/单会话，在最长候选音频窗口与上下文下运行；随后逐档增加并发。每档记录每会话公平性、排队、内存、实际 RTF 和关键错误。停止在明确失败档位，避免只公布成功的短样例。

吞吐必要条件 Σ(C_i/Δ_i)<1 仅是粗略模型；需留余量且实测。支持一个模型的服务引擎不自动保证音频编码动态批次、混合状态和流式提交可高并发。

额外故障：设备 OOM、worker 迟滞、客户端慢读、服务端慢写、单客户端超速发送、长静音、End 与正在运行任务竞态、无法裁剪的长句。

## 11. 本项目首次质量门槛建议

候选：最终 chrF 相对同模型 B0 降幅不超过约 2 分（0–100）；关键否定/数字精选回归无新增错误；真实语义提交 p50 约 2–3 秒、p95 约 5 秒；长流不持续积压。这些是开发目标，需在开发集和业务需求下冻结，不是当前承诺。

必需硬门槛不随硬件调整：无未来输入、无静默回滚/丢音频/串会话、无冒充真实模型的 mock、无未披露 fallback。性能不过可以标为功能原型；正确性不过不能用“已经实时”掩盖。

## 12. 报告审计问题

有没有用完整音频特征？有没有用未来 VAD？是否只报最后一次离线精修？是否把草稿当提交？是否把不能撤回当正确？是否按重叠窗口长度计算 RTF？是否强迫同一前缀后宣称稳定？是否把 CUDA 数字当 NPU 数字？是否把 9B 的复制注释当实测显存？是否省略空输出和失败样例？是否把跳过硬件测试计为通过？

任一答案不清楚，先补证据再接受结论。
