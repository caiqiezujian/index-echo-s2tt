# AutoDL 单卡 RTX 5090：环境与模型准备

核对日期：2026-10-08。目标：先运行 Index-Echo S2TT 2B，再验证英文语音→中文文本，最后接入单会话同传。以下是待在租用实例验证的安装方案；官方依赖曾在 Python 3.12、CUDA 12.9、A100 上验证，我们尚未在 AutoDL 5090 上实测。

## 1. 租用规格与镜像

| 项目 | 建议 | 原因 |
|---|---|---|
| GPU | 1 × 5090，32GB 显存 | 核对租用页面的型号和显存；AutoDL Pro 官方规格列有 `5090-32G` |
| 主机内存 | 2B 首测至少 32GB；准备测 9B 优先 64GB | 为权重加载、解码和音频处理留余量；这是工程预算，非实测最低值 |
| CPU | 优先 8 个可用核心或以上 | 音频解码、特征处理和下载校验会使用 CPU |
| 存储 | 首测 2B 预留约 50GB 可用空间；两模型建议约 100GB | 还要容纳环境、pip/模型缓存、测试音频和日志 |
| 镜像 | 优先官方 Ubuntu 22.04/24.04，Python 3.12，较新的 PyTorch/CUDA 镜像 | 优先 CUDA 12.8 或更新的镜像；最终在独立环境装指定 cu128 wheel |

镜像不必预装完全相同的 PyTorch 版本。运行版本由下面的独立环境决定。不要照搬官方示例中的旧 Python 3.8/CUDA 11.x 镜像。具体可选镜像以租用页面为准，公开文档没有证明当前页面提供哪一个精确组合。

5090 是 Blackwell `sm_120`。PyTorch 维护者确认 CUDA 12.8 构建支持它。候选组合为 **Python 3.12 + torch 2.11.0/cu128 + torchaudio 2.11.0/cu128 + transformers 5.6.0 + BF16**。

## 2. 存储目录与项目上传

普通容器通常有独立数据盘；Pro 的 `/root/autodl-tmp` 是系统盘中的目录，不是独立数据盘。先检查容量，Pro 按需要选择足够的系统盘空间。

在 AutoDL 的 **Linux Bash 终端**执行；以下不是本地 Windows PowerShell 命令：

```bash
nvidia-smi
python --version
df -h / /root/autodl-tmp
free -h

export INDEX_ROOT=/root/autodl-tmp/index-echo
mkdir -p "$INDEX_ROOT"/{code,models,envs,data,reports,tmp,cache/pip,cache/huggingface,cache/modelscope,cache/torch,cache/conda}
export PIP_CACHE_DIR="$INDEX_ROOT/cache/pip"
export HF_HOME="$INDEX_ROOT/cache/huggingface"
export MODELSCOPE_CACHE="$INDEX_ROOT/cache/modelscope"
export TORCH_HOME="$INDEX_ROOT/cache/torch"
export CONDA_PKGS_DIRS="$INDEX_ROOT/cache/conda"
export TMPDIR="$INDEX_ROOT/tmp"
```

将本地 `D:\Index-project` 的代码和文档上传到 `$INDEX_ROOT/code/Index-project`；本指南使用该路径。至少上传 `envs/cuda5090/requirements.in`、`scripts/`、`configs/model_snapshots.json`。可用 AutoDL JupyterLab 上传或 SSH/SFTP，连接地址和端口使用控制台提供的值。权重直接下载到远程实例，不必在本地中转。新终端需重新设置这些变量并激活环境。

`nvidia-smi` 顶部的 CUDA Version 是驱动支持的版本提示；安装后使用 `torch.version.cuda` 确认 PyTorch 自带的运行时。初期使用预编译 wheel，无需另装整套 CUDA Toolkit，也不要自行替换云主机 NVIDIA 驱动。

## 3. 建立 Python 环境

镜像带 Conda 时：

```bash
conda create -p "$INDEX_ROOT/envs/echo-cuda" python=3.12 -y
conda activate "$INDEX_ROOT/envs/echo-cuda"
python --version
python -m pip install --upgrade pip
cd "$INDEX_ROOT/code/Index-project"
```

如果镜像已经提供 `python3.12`、但没有 Conda，改用以下方式，选择其中一种即可：

```bash
python3.12 -m venv "$INDEX_ROOT/envs/echo-cuda"
source "$INDEX_ROOT/envs/echo-cuda/bin/activate"
python -m pip install --upgrade pip
cd "$INDEX_ROOT/code/Index-project"
```

先安装支持 5090 的官方 CUDA wheel，再安装其余依赖：

```bash
python -m pip install torch==2.11.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r envs/cuda5090/requirements.in
python -m pip check
```

`requirements.in` 是候选约束，部分依赖保持官方下限，尚非完整锁文件。安装成功后保存实际版本：

```bash
python -m pip freeze > "$INDEX_ROOT/reports/cuda5090.freeze.txt"
python -m pip --version > "$INDEX_ROOT/reports/pip_version.txt"
nvidia-smi > "$INDEX_ROOT/reports/nvidia-smi.txt"
```

系统需有 `ffmpeg`：

```bash
ffmpeg -version
```

若提示未找到，在 Ubuntu 容器中执行以下安装，再检查版本：

```bash
apt-get update
apt-get install -y ffmpeg
ffmpeg -version
```

首测无需安装 FlashAttention、flash-linear-attention、vLLM 或量化工具；先使用 Transformers 默认实现验证正确性。后续接 `hlt-mt/simulstream` 时安装基础包，避免其 `[hf]` 扩展中的旧 Transformers 约束覆盖 Echo 版本。评估依赖另建环境。

## 4. GPU 与依赖自检

```bash
python scripts/check_cuda_environment.py --out "$INDEX_ROOT/reports/cuda_environment.json"
```

脚本检查 Python/依赖版本、FFmpeg、GPU 型号/容量、计算能力、BF16 矩阵乘法与注意力运算，以及 Echo 所需 Transformers 类。退出码非零时先处理报告中的 FAIL；不要继续把失败包装成模型通过。**环境 PASS 仅表示环境冒烟检查成功，不表示模型推理、英译中或同传已通过。**

如安装 wheel 时网络受阻，先检查对应下载域名是否可达。AutoDL 的 `source /etc/network_turbo` 主要针对 GitHub/Hugging Face；不要假设它一定能加速 PyTorch 源或 ModelScope。

## 5. 下载完整 S2TT 模型

第一阶段只下载 **IndexTeam/Index-Echo-S2TT-2B**。固定快照的文件总量约 **5.90GB（5.50GiB）**。完整包包含 `audio_tower.safetensors`、`connector.safetensors`、`audio_config.json`、`llm/` 下的解码器与 tokenizer，以及官方 `infer.py`。无需另下完整 Qwen3-Omni 或独立 Index-Translate 解码器。

国内实例优先用官方 IndexTeam 的 ModelScope 仓库。脚本固定审查过的 ModelScope revision，逐文件比对发布方 SHA256，并写入下载报告：

```bash
python scripts/download_echo.py --size 2B --root "$INDEX_ROOT/models" --report-dir "$INDEX_ROOT/reports"
```

固定快照：

| 模型 | ModelScope revision | 全包大小 |
|---|---|---|
| 2B | `b98e6e1d15cfd3d1d22093289a7f1b9d9fe66972` | 约 5.90GB |
| 9B | `c4a9dc5689c402963fb231139485064b9aa0cccf` | 约 19.26GB |

大小来自该 revision 的文件元数据，9B 清单排除了发布仓库中的 `__pycache__`；SDK 全量下载可能额外取回该小文件。缓存占用取决于 SDK 实现，存储预算不能只按权重大小估算。ModelScope revision 不可当作 Hugging Face commit 使用。

2B 测试通过后再下载 9B：

```bash
python scripts/download_echo.py --size 9B --root "$INDEX_ROOT/models" --report-dir "$INDEX_ROOT/reports"
```

两模型分开运行。32GB 卡上的 9B 峰值显存、速度和可用窗口长度仍需实测。

## 6. 官方推理检查与英译中验收

先上传一段 10–20 秒、内容清楚的中文音频到 `$INDEX_ROOT/data/zh_smoke.wav`，验证官方支持的中文→英文入口：

```bash
python "$INDEX_ROOT/models/Index-Echo-S2TT-2B/infer.py" "$INDEX_ROOT/data/zh_smoke.wav" \
  --target-lang en --out "$INDEX_ROOT/reports/zh_en_smoke" \
  --device cuda:0 --max-win 20 --ctx-k 0 --max-new-tokens 512 --temperature 0
```

保存 SRT、原始 JSONL、耗时和显存记录。下载或环境自检通过不能替代这次真实权重推理。

**官方 CLI 的目标选项只有 `en/ja/es`；直接添加 `--target-lang zh` 会被拒绝，2B 内部指令表也缺少 `zh`。** 当前仓库尚未实现英译中适配入口。随后需要在项目 backend 中保持权重、音频特征和生成模板一致，增加中文目标指令，使用方向中立的输出解析，并独立验证英文→中文。论文中的完整窗口英译中结果提供依据，但不能替代实际导出包和短前缀测试。

准备同一段英文音频的真实截断前缀，例如 2/4/8/12 秒；记录原始输出、首字延迟、每次更新耗时和峰值显存。通过后再接连续音频接收、调度、草稿/提交策略和 WebSocket。官方文件切窗脚本不是完整同传服务。

## 7. 常见失败与处理

| 现象 | 优先检查 |
|---|---|
| `sm_120 is not compatible` / `no kernel image` | 是否误装了旧 torch 或 cu126；检查激活环境与 `torch.version.cuda` |
| `torch.cuda.is_available()` 为 False | 是否有卡开机、驱动是否正常、是否装成 CPU wheel |
| 导入 `qwen3_5` 或音频编码器失败 | Transformers 是否为 5.6.0，以及报告中的导入错误 |
| pip/下载提示空间不足 | 用 `df -h` 看实际文件系统；Pro 目录可能仍位于系统盘；检查缓存位置 |
| 下载校验失败 | 查看失败文件，重新运行同一固定 revision 下载；不要跳过校验执行模型脚本 |
| 9B OOM | 单独启动、缩短音频窗口/历史/生成预算，记录峰值；回到 2B 完成同传主链路 |
