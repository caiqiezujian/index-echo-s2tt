# 本地 Codex 实施任务书

版本：2026-10-08。先阅读 `01_技术方案.md`、`03_测试与验收规范.md` 和 `04_调查证据与学习资料.md`。

## A. 可直接作为首条任务输入的指令

> 在当前仓库实施 Index-Echo 英中流式同传项目。主线为 simulstream + 独立 SessionCore + IndexEchoBackend；先在 Linux A800/A100 上验证，之后迁移 Ascend 910B。不要先写完整前端，不先加跨更新缓存，不用 mock 冒充模型成功。
>
> 首先检查已有代码与用户修改，不覆盖未提交内容。执行本任务书 T00–T03：现场环境盘点、上游与模型 revision 冻结、官方方向健康检查、2B/9B 组件与英中完整/前缀探针。依据真实环境创建隔离依赖锁，不修改系统驱动、固件、MIG、全局 Python/CUDA/CANN。
>
> 已给定硬件方向，不重复询问使用哪类卡。实际显存、CPU 架构、现有版本、可用模型路径等优先通过只读检查获取。没有硬件/权重时将真实模型测试标 BLOCKED，可以继续实现纯逻辑测试，但不得把结果标为模型通过。
>
> 逐任务提交真实可执行的代码和测试。每阶段报告 PASS/FAIL/BLOCKED、实际命令、版本、原始日志、失败样例及下一项工作。未实施命令必须标为拟议接口。不得悄悄换成 ASR+文本翻译、CPU fallback 或外部 API 后声称 Echo/Ascend 成功。
>
> 完整英中或组件检查未通过时，先诊断而不是进入并发/缓存/量化优化。普通安全实现步骤可以顺序推进，不因每个小改动反复等待确认；系统环境变更、数据外传、付费或破坏性操作仍需明确授权。

## B. 不可违反的工程合同

模型只能看到已交付音频切片；不得整文件 VAD、整文件特征后切片、未来转写或金标对齐进入在线推理。读完整文件的权限只属于独立离线参考/评分路径。

收到音频、模型实际看到音频、源音频允许删除是三个不同光标；提交的中文长度不能换算成裁剪时刻。

草稿允许改写；已提交文字不得静默回滚。冲突有明确事件，错误计入指标。强制模型复写前缀不能当作两轮独立一致证据。

2B、9B 各自检查 connector、prompt、配置和权重键。内部源/目标字段不使用旧 zh/en 语义硬编码。实际组件与所有权重严格加载，禁止用 strict=False 遮掩关键缺失。

至少分 CUDA、Ascend、evaluation 三套依赖。硬件无关代码不得全局导入平台专属模块。Ascend 迁移禁止全仓替换 cuda→npu，必须具备逐组件回归。

默认一张卡一个模型 worker，一个运行任务和一个待执行最新快照。合并任务不能丢输入；旧结果不能覆盖新状态；End 必须覆盖最后确认接收样本。

## C. 实施任务分解

### T00：仓库和现场盘点

输入：当前工作目录、用户已配置服务器。

只读检查：版本控制状态、文件结构、运行文档、可见设备、CPU 架构、OS、RAM/磁盘、Python/包版本、现有模型路径与访问权限。

NVIDIA 记录 nvidia-smi、GPU UUID/显存/MIG/驱动/拓扑；Ascend 记录 npu-smi、驱动固件/CANN、CPU 架构。相关命令不存在时原样报告，不伪造安装成功。

产物：`reports/environment_inventory.md`、`reports/blockers.md`。

通过：已识别实际资源及权限，未知项清楚列出。禁止在本任务安装或升级系统驱动。

### T01：上游与依赖冻结

拉取明确选用的公开源码，记录完整 commit、仓库来源、许可、本地补丁。模型记录完整 HF revision、关键脚本/配置 SHA256、分片清单、tokenizer 和组件文件。

以 Echo 官方声明 Torch 2.11.0、Transformers 5.6.0 为候选；检查实际 requirements，选择与 GPU 驱动匹配的 wheel。NPU 独立查 TorchNPU/CANN/驱动矩阵，不将开发主机安装命令直接搬过去。

产物：`upstream_manifest.json`、`envs/cuda.lock`、候选 `envs/ascend.lock`、`envs/eval.lock`，以及依赖选择记录。未能验证的 lock 标为 candidate，不能作为已跑通组合。

通过：CUDA 运行环境可重建；模型下载完整；NPU 版本交集或阻塞原因可追踪。

### T02：保持官方加载语义的后端

实现组件解析和加载日志；使用官方脚本健康检查作参考。验证 2B/9B 的 connector 分支、隐藏维度、特殊 token 与音频占位符数量。避免不必要的视觉组件加载，但不得擅自删除模型需要的配置。

保留原文件路径作为只读参考，实现内存音频路径；比较同一规范化 WAV 的特征、长度、embedding 与输出。

产物：`backends/index_echo.py` 或等价模块、真实模型合同测试、加载/差异报告。

通过：至少 2B 完整链路真实运行；9B 未下载/未跑时单独标状态。

### T03：英中与前缀探针

先完整英语音频，再严格裁剪的多个前缀；补充中文目标指令时沿用原三行格式。记录所有原始输出、源转写、目标译文、时间戳、生成结束原因和运行耗时。

检查路由、源/目标字段、否定/数字/专名、后文补全幻觉。2B/9B 分开出结果，不复用健康结论。

产物：样例 manifest、原始 JSONL、逐例轨迹和错误分类。

通过：英中能力可客观评估；未通过先定位，不进入性能包装。

### T04：音频规范化与台账

实现连续重采样、绝对采样点、帧序号、缺口标记、不可变快照和可见边界限制。在线路径只接收已交付切片。

产物：AudioNormalizer、AudioLedger、单位/性质测试。

通过：整段/分块规范化差异在定义范围内；未来样本诱饵不影响提前输出；重复/乱序/缺失行为明确。

### T05：解析器与假设结构

解析三行格式，保留 raw_text，统一 source_text/target_text。识别尾部截断、空译文、非法时间戳、超出快照、重复和多行异常，不制造置信度。

产物：Hypothesis/Cue 数据结构、Parser、源区间比较与测试。

通过：异常输入不会被误记为稳定完整译文；中文 Unicode 与真实重复样例通过。

### T06：纯逻辑 SessionCore 与事件台账

实现状态机、任务版本、三个光标、音频结束/取消、事件序列和原子提交/草稿更新。先用明确命名的 mock 测试调度正确性。

产物：SessionCore、EventLedger、版本/恢复/过期任务测试。

通过：无静默回滚、旧结果覆盖、状态串线或尾段遗漏。报告中注明此时 mock 只验证逻辑。

### T07：B1/B2 提交策略与历史

先实现边界保守策略，再加入同一 epoch、真实新增音频的 LA2/LA3。自由假设与已提交前缀冲突时显式处理。上下文 epoch 内冻结，术语更新引发策略版本变化。

音频裁剪必须有源区间依据；不按目标字符数裁剪。跨 epoch 重置比较，区分重叠重复与真实重复讲话。

产物：策略模块、历史管理、关键否定/数字/漏译回归。

通过：L1 与 L2 能力分开报告；不因只出现草稿而宣称句中提交成功。

### T08：真实模型的因果回放

隔离完整录音读取器与模型接口。先 computation-unaware 算法模式，再 1× wall-clock 模式。记录 received/used/evicted、推理/排队/展示的事件时间。

产物：回放 CLI、日志 schema、B0/B1/B2 对照。

通过：真实权重运行证据与因果测试同时存在，未读未来；计算时间没有被隐藏。

### T09：simulstream 接入与最小字幕

核对当前 SpeechProcessor、BaseSpeechProcessor、IncrementalOutput 的实际接口，做外部 adapter。不要直接复制 README 中可能过期的 import。

将上游增删输出与稳定台账映射；先最小 UI。同步推理在受控 worker 中，不堵音频接收。回归至少一个上游自带处理器的基本合同，避免改坏框架。

产物：adapter、配置、启动/演示说明、真实实时日志。

通过：麦克风/回放两条路径可追踪，草稿/提交视觉与数据语义一致。

### T10：NVIDIA profiling 与质量—延迟研究

独占 A800/A100，记录真实 SKU/资源。比较单变量步长、尾部保留、上下文、token 上限与 2B/9B。分开编码/prefill/decode/排队，正确计算唯一音频口径 RTF。

先修显著重复加载/I/O，再考虑支持的优化。不同时打开量化、图模式和跨更新缓存。

产物：配置对照表、失败样例、内存/积压趋势、建议配置。

通过：有真实延迟与质量曲线，且保留未优化参考。

### T11：长流、异常、准入与并发

按测试规范执行 30 分钟以上连续流、取消/重连/结束/超载；然后按并发档位扩展。每卡一个模型副本起步，独立会话队列与公平调度。

产物：soak 报告、容量曲线、错误/超载合同。

通过：资源不持续发散；明确最大已验证并发，而非口头估算。

### T12：Ascend 设备层与依赖探针

只在独立环境添加 TorchNPU/provider。生成 CUDA-only import/kernel 清单；检查标准 PyTorch 路径、数据类型、累积状态、索引和同步。

产物：AscendProvider、版本 matrix、算子覆盖 CSV、最小运算验证。

通过：无隐藏全局 CUDA 依赖；CPU 核心测试仍可无 NPU 运行。

### T13：Ascend 逐组件与固定目标序列对照

按 CPU 特征→音频塔→connector→embedding 注入→decoder 单步→固定目标 token 轨迹→自由生成顺序，对照 CUDA 参考。

保存首个差异和误差分布，区分舍入/自由生成分叉与真正错误。记录 CPU fallback。

产物：跨设备对照报告和受支持算子/精度清单。

通过：完整 Echo 在 NPU 实际执行，并有可解释质量；只有文本模型跑通不能通过。

### T14：双平台流式回归

同数据、同提示、同策略运行 B0/B1/B2；报告各自显存、时间、质量、稳定性和容量。再调整平台性能参数时另开配置，不能混作同配置对照。

产物：CUDA/NPU 并列表、各自 PASS/FAIL/质量等级。

通过：两个平台独立满足验收，或清晰说明哪个指标未达。

### T15：可选原生 gRPC

共用 core，不重写稳定算法。实现 Start/Audio/End/Cancel/Ack、序号、幂等重连、最大消息与会话限制、超时和鉴权。浏览器继续使用 WS。

产物：proto、真实生成的 stub、客户端和协议合同测试。

通过：相同模拟输入下 WS/gRPC 的语义事件等价；网络性能单独统计。

### T16：优化或训练实验

仅凭已有瓶颈进入：安全跨更新缓存、专用引擎、量化、注意力门控、prefix SFT 或因果音频塔。每个实验有可关闭 flag、数据/环境冻结、原参考和独立回归。

产物：设计决策记录、实验表、回退路径。

通过：收益成立，未把最终离线输出冒充在线质量。

## E. 命令使用约束

系统盘点命令可只读执行。模型、数据下载规模与路径要记录；不要自动下载全部候选模型，不在 Git 仓库提交权重。新的 CLI 是本项目交付的一部分，实现后才写入可运行说明。

所有镜像、驱动和硬件操作遵守用户权限。发现系统不兼容时写出阻塞与最小修复建议，不能靠改全局环境把另一平台或已有服务破坏。
