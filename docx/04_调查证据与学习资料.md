# 三轮调查、证据边界与学习资料

核查日期：2026-10-08。来源为维护者仓库、官方模型卡/源码、厂商文档和作者论文。未把二手文章、搜索摘要或旧对话中的性能数字作为部署验收依据。

## 1. 三轮调查的可追溯结果

### R1：可复用开源系统与接口

调查问题：是否有可插入自定义模型的同传系统？哪些传输、展示、评测可以复用？

结论：simulstream 有自定义 SpeechProcessor 和实时/回放入口，适合作为底座；需要自建稳定提交/更正台账。gRPC 可作为额外原生入口，不能替代翻译策略。浏览器使用 WebSocket 可避免把 grpc-web 错当成原生双向流。

证据：S01、S02、S03、S15、S16、S17、S19。

尚未确认：现成 Echo 英中插件、生产级鉴权/恢复、完整 NPU 接入。它们在方案中都是待实现/待验收项。

### R2：Echo 代码、方向、组件与缓存

调查问题：模型如何接收音频？2B/9B 是否同构同接口？公开脚本是否在线？

结论：完整文件 VAD 与分窗生成不是在线会话；2B/9B 目标指令及 connector 加载存在差异；输出旧字段名不能代表实际源/目标语言；2B 的混合注意力配置影响缓存和设备迁移。

证据：S04、S05、S06、S07。

尚未确认：实际权重的完整英中/短前缀质量；任一具体显存配置下的长流速度；安全跨更新缓存。必须由 M1、M4 和后续实验回答。

### R3：稳定策略、长流评测与双硬件部署

调查问题：如何提交、不漏音频、衡量真实时延？如何从 A800/A100 迁移到 910B？

结论：重译和 LocalAgreement 提供首个基线；音频历史选择是独立问题；注意力/因果塔需要额外适配。TorchNPU 有与 Torch 2.11 对应的版本组合，但完整 Echo 算子/设备支持仍需验证。Qwen3.5 的 vLLM-Ascend 支持不构成 Echo 整包兼容证明。

证据：S08–S14、S18–S25。

尚未确认：用户具体板卡/驱动/固件的组合；完整 Echo NPU 算子覆盖；CUDA/NPU 质量差；实际并发和延迟目标。

核实范围：抽象处理器与部分实现的区分。编码时以锁定版本实际 import/构造器为准，不从 README 拼接假 API。

核实范围：新增/删除 token 或字符串的输出方式。它不包含本方案完整的稳定提交、更正与恢复协议。

### S04｜Index-Echo-S2TT-2B 官方模型卡

`https://huggingface.co/IndexTeam/Index-Echo-S2TT-2B`

核实范围：组件文件、发布接口、英中评测与发布能力的区分、官方推理环境声明。PyTorch 2.11.0 / Transformers 5.6.0 是复现起点，不是本次已在用户机器测试的依赖锁。

### S05｜Index-Echo-S2TT-2B 官方推理脚本

`https://huggingface.co/IndexTeam/Index-Echo-S2TT-2B/blob/main/infer.py`

核实范围：组件加载、音频表示注入、三行生成模板、en/ja/es 目标指令、完整文件 VAD 和逐窗处理。本文只概括适配入口，不复制上游完整实现。

### S06｜Index-Echo-S2TT-9B 官方推理脚本

`https://huggingface.co/IndexTeam/Index-Echo-S2TT-9B/blob/main/infer.py`

核实范围：含中文目标指令；增加投影式 connector 并依据权重键选择；命令行仍有限制。应独立核查 9B；共用代码注释中的显存/速度不能作为实际测量。

### S07｜Echo 2B 解码器配置

`https://huggingface.co/IndexTeam/Index-Echo-S2TT-2B/blob/main/llm/config.json`

核实范围：Qwen3.5 配置、混合完整/线性注意力层及状态相关配置。没有据此推定任意引擎/硬件已支持完整 Echo。

### S08｜TorchNPU 官方兼容矩阵

`https://github.com/Ascend/pytorch/blob/master/COMPATIBILITY.en.md`

核实范围：TorchNPU/PyTorch/CANN/Python 组合。本次可见 PyTorch 2.11.0 + TorchNPU 2.11.0.post2 + CANN 9.1.X；实际机器还须核对驱动、固件和具体产品支持。表格版本会变化，实施时记录 commit。

### S09｜Ascend PyTorch 适配器官方仓库

`https://github.com/Ascend/pytorch`

核实范围：TorchNPU 的平台角色、安装和版本来源。不能用张量矩阵乘样例通过代替 Echo 全模型通过。

### S10｜vLLM-Ascend 维护者仓库

`https://github.com/vllm-project/vllm-ascend`

核实范围：Ascend 硬件插件、支持矩阵入口和依赖要求。所查 README 的 Torch/TorchNPU 要求与 Echo 声明的主版本不完全相同，因此该引擎应有独立环境和回归。

`https://docs.vllm.ai/projects/ascend/en/latest/user_guide/support_matrix/supported_models.html`

核实范围：检查当前列表；页面检索未出现 Index。未出现不是“绝对不可适配”，而是不能宣称已有明确的官方整包支持。

### S13｜NVIDIA Ampere 调优指南

`https://docs.nvidia.com/cuda/ampere-tuning-guide/index.html`

核实范围：Ampere Tensor Core 的 BF16 等能力。支持把 BF16 作为参考精度起点，不提供 Echo 吞吐/显存测量，也不代表所有自定义算子都高效。

### S14｜NVIDIA A800 40GB Active 官方页

`https://www.nvidia.com/en-us/products/workstations/a800/`

核实范围：A800 存在不同于“默认 80GB”的具体型号。只是说明必须做现场 SKU/显存盘点，不能用此页推定用户服务器就是该产品。

### S15｜gRPC 官方核心概念

`https://grpc.io/docs/what-is-grpc/core-concepts/`

核实范围：双向流与调用生命周期。传输流式不等于翻译决策或模型音频计算原生流式。

### S16｜grpc-web 官方仓库

`https://github.com/grpc/grpc-web`

核实范围：当前官方实现不支持客户端流和双向流。本方案浏览器使用 WebSocket，原生 gRPC 入口另外实现。

### S17｜gRPC 官方流控

`https://grpc.io/docs/guides/flow-control/`

核实范围：网络/框架层流控。应用仍须设置音频缓冲和模型任务上限，避免把网络背压当成可无限暂停真实麦克风。

### S18｜Whisper-Streaming 作者仓库

`https://github.com/ufal/whisper_streaming`

核实范围：含新增音频的连续假设一致性、缓冲、计算感知/不感知模拟。仅借鉴方法，不转用其 Whisper 测试延迟作为 Echo 性能。

### S19｜simulstream 作者论文

`https://arxiv.org/html/2512.17648v2`

核实范围：可扩展语音处理器、连续输入和评价/演示的设计。具体命令与指标实现仍以本地冻结源码为准。

### S20｜StreamAtt 作者论文

`https://arxiv.org/abs/2406.06097`

核实范围：面向直接流式 S2TT 的音频历史选择问题。最值得借鉴的是把何时输出和保留多少历史分开研究，而不是直接继承论文配置。

### S21｜AlignAtt4LLM 作者仓库

`https://github.com/QuentinFuxa/Alignatt4LLM`

核实范围：decoder-only 翻译的注意力策略和实现入口。不证明 Echo 音频模型已接入。

### S22｜AlignAtt4LLM 新模型适配指南

`https://github.com/QuentinFuxa/Alignatt4LLM/blob/main/docs/adding_a_model.md`

核实范围：新增翻译模型适配所需合同。应先用于文本 Index-Translate 对照，再评估 Echo 音频位置/混合注意力的额外工作。

### S23｜AlignAtt4LLM 作者论文

`https://arxiv.org/html/2606.03967v1`

核实范围：方法、实验和局限。不能把别的模型或语种的注意力头配置、质量与时延直接套到英中 Echo。

### S24｜Qwen3-ASR-causal 作者仓库

`https://github.com/QuentinFuxa/Qwen3-ASR-causal`

核实范围：专门微调的因果音频塔、跨块状态与运行时；作者披露速度、质量和语言限制。它是编码器研究资料，不是可直接替换 Echo 的塔，也不是本次实测。

### S25｜Re-Translation Strategies 作者论文

`https://arxiv.org/abs/1912.03393`

核实范围：连续重译及增量不稳定性的研究背景。不能由级联论文结果推断 Echo 的迁移效果。

补充学习入口：Whisper-Streaming 论文元信息：
`https://aclanthology.org/2023.ijcnlp-demo.3/`

## 3. 阅读顺序与产物要求

第一步读 S04–S07，产出模型输入/输出、组件、方向与缓存合同。

第二步读 S01–S03、S15–S17，产出自定义处理器与会话事件映射，不先写复杂前端。

第三步读 S18–S20、S25，产出 B0/B1/B2、音频历史与真实时间评测设计。

第四步读 S08–S14，产出环境冻结和算子/硬件矩阵，先 CUDA 再 NPU。

最后才读 S21–S24 深入门控和因果塔，产出单独研究分支与精度/计算回归。读完论文不等于已验证迁移。
